# Modelo de dados — Mekano Supplies Purchase Request Service API

**Banco:** `mekano_supplies` (PostgreSQL 16)
**Migrations:** `supplies-infrastructure/src/main/resources/db/migration`

---

## 1. Princípios

- Uma **migration final por tabela**, já com todas as colunas, tipos, constraints e índices.
- Sem migrations de correção nesta fase acadêmica.
- `BIGINT GENERATED BY DEFAULT AS IDENTITY` como PK.
- `UUID` único exposto na API.
- Auditoria com `created_at`, `updated_at`, `created_by`, `updated_by`.
- **Sem FK cross-database** para `peca_uuid` (referência lógica ao Registry).
- Estoque e NF sempre na mesma transação local.
- `idempotency_key` única no ledger de estoque.

### 3.3 `estoque`

| Coluna | Tipo | Regras |
|---|---|---|
| `id` | `BIGINT` | PK, identity |
| `uuid` | `UUID` | NOT NULL, UNIQUE |
| `peca_uuid` | `UUID` | NOT NULL, UNIQUE, referência lógica ao Registry |
| `saldo_atual` | `BIGINT` | NOT NULL DEFAULT 0, CHECK >= 0 |
| `saldo_reservado` | `BIGINT` | NOT NULL DEFAULT 0, CHECK >= 0 |
| `estoque_minimo` | `BIGINT` | NULL, CHECK >= 0 |
| `version` | `BIGINT` | NOT NULL DEFAULT 0 |
| `created_at` | `TIMESTAMP` | NOT NULL |
| `updated_at` | `TIMESTAMP` | NULL |

Regras:

- `disponivel = saldo_atual - saldo_reservado` (calculado, não persistido).

- `obterOuCriar` cria a linha com saldo 0 quando a peça é referenciada pela primeira vez.

Índices:

- `ux_estoque_uuid` UNIQUE (`uuid`)
- `ux_estoque_peca_uuid` UNIQUE (`peca_uuid`)
- `ix_estoque_abaixo_minimo` (`estoque_minimo`)

## 4. Regras de estoque

| Tipo | Efeito | Validação |
|---|---|---|
| `CREDITO` | `saldo_atual += qtd` | quantidade > 0 |
| `DEBITO` | `saldo_atual -= qtd` | `saldo_atual >= qtd` |
| `RESERVA` | `saldo_reservado += qtd` | quantidade > 0 |
| `LIBERACAO` | `saldo_reservado -= qtd` | `saldo_reservado >= qtd` |
| `CONSUMO` | `saldo_atual -= qtd` e `saldo_reservado -= qtd` | ambos >= qtd |

- `disponivel = saldo_atual - saldo_reservado`.
- Estoque abaixo do mínimo: `estoque_minimo IS NOT NULL AND disponivel <= estoque_minimo`.
- Movimentos sempre geram registro no ledger.
- Duplicata de `idempotency_key` retorna o movimento existente, sem alterar saldo.

## 5. Fluxo transacional da NF

### 5.1 Registrar

```text
BEGIN
  valida requisição PRODUTO_RECEBIDO
  valida chave 44 dígitos única
  valida valor > 0
  INSERT nf_entradas (status=ATIVA)
  para cada item da requisição:
    UPDATE estoque SET saldo_atual = saldo_atual + qtd
    INSERT movimentos_estoque (CREDITO, idempotency_key=nf:<uuid>:<pecaUuid>:CREDITO)
COMMIT
```

Falha em qualquer etapa → rollback total.

### 5.2 Cancelar

```text
BEGIN
  valida NF ATIVA
  para cada item da requisição:
    UPDATE estoque SET saldo_atual = saldo_atual - qtd
      WHERE saldo_atual >= qtd
    INSERT movimentos_estoque (DEBITO, idempotency_key=nf:<uuid>:<pecaUuid>:ESTORNO)
  UPDATE nf_entradas SET status=CANCELADA, motivo_cancelamento=?, data_cancelamento=NOW()
COMMIT
```

Falha por saldo insuficiente → `409` + rollback; NF permanece `ATIVA`.

## 6. Seed (`V6__seed_estoque_inicial.sql`)

| Peça | UUID | saldo_atual | saldo_reservado | estoque_minimo |
|---|---|---|---|---|
| `PEA-001` | `55555555-5555-5555-5555-555555555555` | 10 | 0 | 2 |
| `PEA-002` | `66666666-6666-6666-6666-666666666666` | 5 | 0 | 3 |

Regras:

- Inserção idempotente com `WHERE NOT EXISTS (SELECT 1 FROM estoque WHERE peca_uuid = ?)`.
  Equivale ao `ON CONFLICT (peca_uuid) DO NOTHING` do PostgreSQL, mas também
  executa no H2 usado pelo smoke test de migrations.
- `created_by = 'SEED'`.
- O catálogo correspondente é criado pelo seed do Registry.

---

## 7. Convenções de migration

- Usar `BIGINT GENERATED BY DEFAULT AS IDENTITY`.
- Não usar `BIGSERIAL`.
- Não agrupar múltiplos `ADD COLUMN` em uma linha.
- Nomear constraints e índices explicitamente.
- `TIMESTAMP` sem timezone, seguindo o padrão do monólito.
- `NUMERIC(12,2)` para valores monetários.
- `CHAR(44)` para chave de acesso da NF.
